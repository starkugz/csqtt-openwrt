# Диагностика и восстановление

Диагностика панели CSQTT 2.5 и клиентских ядер 2.1.9/2.5.3. Секреты (`password`, VK-токен, VK-хеши,
`device_id`) в логах и статусе маскируются; не публикуйте вывод, если сами
добавили в него секрет.

## Типовые симптомы

| Симптом | Возможная причина | Безопасная проверка | Действие |
|---|---|---|---|
| Служба «не запущена» | `main.enabled='0'` или нет автозапуска | `uci get csqtt.main.enabled`; `ls /etc/rc.d/*csqtt*` | `uci set csqtt.main.enabled='1'; uci commit csqtt; service csqtt enable; service csqtt start` |
| Профиль выключен, соединения нет | профиль `enabled='0'` | `uci -q get csqtt.<id>.enabled` | включить профиль в панели или `uci set csqtt.<id>.enabled='1'; uci commit csqtt` |
| Нет интерфейса `csqtt0` | служба не запущена или TUN не поднялся | `ip -4 addr show csqtt0` | проверьте службу; `csqtt doctor` |
| Туннель есть, трафика нет | нет привязки прокси к `csqtt0`, либо правила клиента | `curl --interface csqtt0 --max-time 15 https://1.1.1.1/cdn-cgi/trace` | настройте выход клиента с `interface-name: csqtt0` ([совместимость](compatibility.md)) |
| Ошибка авторизации VK / Flood | токен недействителен, истёк/отозван, не тот аккаунт; или Flood | `csqtt status` → последняя ошибка; поле **Токен доступа VK** | получить новый токен или использовать `vkcalls` с VK-хешами. **Не запускайте повторные авторизации сериями** |
| Нет соединения при живом сервисе | профиль не соответствует выданной ссылке | `csqtt doctor` | сверьте `host:port` и пароль с выданной ссылкой; `profile use <id>` |
| Периодические тайм-ауты | неподходящие `obfs`/`workers` | — | подберите `obfs` (`audio`/`video`) и `workers` (2.1.9: 9..126 с шагом 9; 2.5.x: 10..100 с шагом 10) по рекомендации владельца сервера |
| Ядро недоступно в панели | пакет этого ядра не установлен | `ls /usr/bin/csqtt-*` | установите нужное ядро или выберите доступный движок; подмены ядра нет |

`uci show csqtt`, `uci export csqtt` и файл `/etc/config/csqtt` могут содержать
пароли, токены и другие секреты. Не отправляйте их целиком в чат, issue или
публичный журнал. Для проверки используйте точечные команды ниже.

## Основные команды

```sh
csqtt status                 # 0 подключён / 1 нет / 2 служба не запущена
csqtt doctor                 # read-only: конфиг, TUN, peer, rp_filter
csqtt doctor --pre-launch
csqtt log tail -n 80 -f      # журнал с маскировкой секретов
logread | grep csqtt         # системный журнал
uci -q get csqtt.main.enabled
```

## Установка и импорт профиля

### Скачивание завершается без вывода

Запустите `wget` отдельно от установщика. При успехе временный файл должен быть непустым.

```sh
(
  f=$(mktemp) || exit 1
  trap 'rm -f "$f"' EXIT
  wget -T 30 -O "$f" https://raw.githubusercontent.com/starkugz/csqtt-openwrt/refs/heads/main/install.sh &&
    test -s "$f" && wc -c "$f"
)
```

Если `wget` возвращает код 0 без файла, проверьте размер исполняемого файла:
`ls -lL "$(command -v wget)"`. Если на OpenWrt с APK установлен `wget-ssl`,
переустановите его командой `apk fix wget-ssl`. Для CSQTT можно сразу
запустить этот резервный вариант:

```sh
(
  f=$(mktemp) || exit 1
  trap 'rm -f "$f"' EXIT
  url=https://raw.githubusercontent.com/starkugz/csqtt-openwrt/refs/heads/main/install.sh
  if { curl -fsSL --connect-timeout 15 --max-time 60 -o "$f" "$url" && [ -s "$f" ]; } ||
     { : >"$f"; uclient-fetch -T 30 -O "$f" "$url" && [ -s "$f" ]; }; then
    ash "$f"
  else
    printf '%s\n' 'Не удалось скачать установщик CSQTT.' >&2
    exit 1
  fi
)
```

При несовпадении SHA-256 вложенного скрипта (например, `installer.sh`)
скачайте установщик заново по адресу из инструкции. Для пакета повторно
скачайте сам пакет и `SHA256SUMS` одного выпуска. Продолжайте установку
только после успешной проверки.

### Панель по HTTP не расшифровывает ссылку

Если панель показывает ошибку формата ссылки или установщик сообщает о пустом
ответе при загрузке `SHA256SUMS` всеми загрузчиками, проверьте системный таймер:

```sh
ls -lL /usr/bin/timeout
/usr/bin/timeout 5 /bin/echo timeout-ok
```

Ожидаемый вывод второй команды — `timeout-ok`. При открытии панели по HTTP
роутер использует таймер для запуска локальной расшифровки. Пустой бинарник
может вернуть код 0 без вывода, и панель покажет общую ошибку формата.
На OpenWrt с APK восстановите установленный пакет командой
`apk fix coreutils-timeout`, повторите проверку и нажмите **Предпросмотр**.
Если таймер работает, проверьте, что ссылка скопирована целиком и экспортирована
в поддерживаемом формате. При обращении за помощью скройте ссылку и секреты.

Если сбой появился после установки SSClash-Go, проверьте утилиты теми же
командами. Совпадение по времени не устанавливает причину. В проверенном
случае расшифровка заработала после восстановления таймера при работающем
SSClash-Go и без изменения правил Fake-IP.

### Ошибки APK

При `Exec format error` зафиксируйте, на каком пакете или индексе возникла
ошибка, и проверьте доступ к репозиторию и соответствие пакета версии и
архитектуре прошивки. При `UNTRUSTED signature` APK не доверяет подписи.
Используйте пакет из доверенного репозитория этой прошивки и штатные ключи APK.

## Восстановление

1. Остановите службу: `service csqtt stop`.
2. Сверьте настройки в LuCI; при подозрении на повреждение
   восстановите `/etc/config/csqtt` из резервной копии (создаётся при установке
   и обновлении, права `0600`).
3. Запустите снова: `service csqtt start`, затем `csqtt doctor`.

## Что не делать

- Не генерируйте новый `device_id` — он привязан к паролю на сервере.
- Не «улучшайте» сетевой контракт: не добавляйте маршруты/rules/NAT/DNS.
- Не публикуйте сырые логи и резервные копии — в них могут быть адреса и
  метаданные.
- Не запускайте повторные авторизации VK сериями (риск Flood).

## CAPTCHA

Если панель предлагает решить CAPTCHA, используйте встроенный решатель или
локальную страницу Web Helper (ссылка и QR на странице **CAPTCHA**). Не
запускайте повторные авторизации, пока задача активна. Детали — в
[панели LuCI](luci.md).
