# Установка сервера CSQTT на Linux

Для установки нужны права root, Linux с systemd и TUN. Используйте
сервер 2.1.9 для существующих клиентов 2.1.9. Сервер 2.5.3 предназначен
для клиентов ветки 2.5.x. При обновлении действующего сервера проверьте
совместимость клиентов и сохраните конфигурацию.

| Сервер | Платформы в комплекте |
|---|---|
| 2.5.3 | x86-64, AArch64, ARMv7 |
| 2.1.9 | x86-64, оригинальный бинарник amurcanov из выпуска [v2.0](https://github.com/starkugz/csqtt-openwrt/releases/tag/v2.0) |

## Подготовка VPS

На минимальном образе Linux сначала подготовьте зависимости. Для Debian/Ubuntu
выполните от root (для обычного пользователя используйте `sudo`):

```sh
apt-get update && apt-get install -y bash ca-certificates curl coreutils iproute2 iptables procps python3 tar
```

Нужны `bash`, `curl`, `sha256sum`, `python3`, `tar`, `od`, `ip`, `ss`,
`sysctl` и, для стандартного режима с NAT, `iptables`. В другой системе
установите соответствующие пакеты её менеджером. Скрипт не устанавливает
systemd и не переключает систему на него.

Проверьте окружение перед запуском:

```sh
command -v systemctl && test -d /run/systemd/system && test -c /dev/net/tun
```

Если проверка завершилась ошибкой, сначала проверьте поддержку systemd и TUN
у провайдера VPS. Для контейнерного VPS доступ к TUN может требовать настройки
на стороне провайдера. Установщик не может включить эту возможность извне.

При отсутствии утилит серверная обёртка завершится до загрузки файлов,
перечислит недостающее и покажет команду подготовки. `--dry-run` тоже требует
зависимости, но сам ничего не устанавливает. После подготовки повторите
обычную команду ниже. Удаление не требует утилит, нужных только для установки.

Выполните команду на VPS от root, чтобы открыть меню установки.

```sh
curl -fsSL https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/install.sh | sh
```

Если вы вошли обычным пользователем и используете `sudo`, замените `| sh` на `| sudo sh`.

В меню можно установить 2.1.9 или 2.5.3, удалить службу с сохранением
данных или отменить действие. Для предварительной проверки выберите
версию напрямую и добавьте `--dry-run`.

```sh
curl -fsSL https://raw.githubusercontent.com/starkugz/csqtt-openwrt/main/install.sh | sh -s -- 2.5.3 --dry-run
```

Установщик проверяет SHA-256 выбранного ELF и скрипта развёртывания.
Серверные бинарники и контрольные суммы находятся в [папке сервера](../../server/v2.5.3).

Установщик настраивает службу systemd, конфигурацию и сетевые ресурсы
сервера. Параметры службы, порты и варианты развёртывания доступны через
[скрипт развёртывания](../../server/backend.sh). После установки выполните
`systemctl status csqtt` и проверьте соединение с клиентом выбранной версии.
Для диагностики используйте `journalctl -u csqtt`. При запуске именованного
экземпляра указывайте его имя службы.

## После установки

1. Откройте HTTPS-адрес сервера с портом веб-панели. Для стандартного
   экземпляра используются UDP-порт `46000` для подключения клиентов и
   TCP-порт `46002` для веб-панели.
2. Проверьте доступ снаружи. Для VPS проверьте также сетевые правила
   провайдера. Если задан другой порт, используйте его и в настройках клиента.
3. Передайте клиенту ссылку подключения или адрес сервера с портом
   и пароль туннеля. Пароль панели храните отдельно.

### Если сервер не запускается

Проверьте `systemctl status csqtt`, последние сообщения
`journalctl -u csqtt -n 50` и наличие `/dev/net/tun`. При конфликте
портов выясните, какой процесс их занимает, и выберите свободные порты.
При ошибке сертификата проверьте доменное имя и цепочку TLS на HTTPS-порту
панели.

Установка роутера описана в [инструкции OpenWrt](install.md).
Лицензия и обязательные уведомления находятся рядом с [бинарниками](../../server/v2.5.3).
